# TYP — Progress & Launch Readiness

A running, plain-language snapshot for tracking "how close are we" — updated after each work session, not a one-time spec. For full technical detail on any item, see `CLAUDE.md` (current-state summary) and `docs/build-log.md` (full history of what was built and how it was verified).

**There is no single honest "% done" number for this project** — engineering completeness, content, live-key testing, QA, deployment, and legal are separate tracks that don't collapse into one metric. This file breaks progress down by track instead of faking a headline percentage, and avoids giving a calendar estimate without a defined launch scope, since the actual bottleneck (content authoring) isn't something more code can shortcut.

### 2026-08-18

- **Course lessons can now be marked as complete, and the dashboard's "study streak" reflects that, not just practice tests.** Previously the only way to keep a streak alive was submitting a practice test — a student working through course lessons every day but not taking tests would show a 0. Now completing a lesson counts too, on both web and mobile, and the same "Study Streak" achievement badge can be earned either way. This also closes a real gap: there was previously no way to track which lessons a student had actually finished at all.
- **A full anti-cheat audit (before/during/after an exam, web and mobile both) found the system is real and working as designed** — eligibility checks, no-clock-reset resuming, tab-switch logging, server-side grading, and duplicate-submission protection are all genuine and consistent across both platforms. The one real gap it found — school admins couldn't see which of their own students' exam attempts got flagged for excessive tab-switching, only a super admin could see a platform-wide snapshot — is now fixed with a new "Flagged Attempts" page under Assessments.
- **Fixed a real mobile bug the same audit surfaced**: if a student's exam timer ran out while the app was closed or backgrounded, the app would fail to show their results at all (a "not found" error) instead of grading the exam with whatever was answered so far — the website already handled this correctly, the app just never actually finished submitting on its end. Now fixed to match.
- **Leaving an exam mid-way (back button, closing the tab/app) now shows a warning and gets logged, on both web and mobile.** Previously a student could walk away from an in-progress exam with the back button and it left no trace at all — unlike switching to another app/tab, which was already being logged. It still doesn't block or auto-submit anything (matches the existing "log it, don't stop them" approach) — it just warns them first and records that it happened, the same way tab-switching already does.
- **The website's dashboard sidebar/menu is no longer visible while taking an exam** (user-requested) — previously a student could just click "Dashboard" or any other menu item in the sidebar to leave an exam with zero warning and zero record of it, a real escape route the back-button fix above couldn't catch since it's just a normal link click. The exam screen is now a clean, full-screen view with no sidebar, no notification bell, no sign-out menu — the only ways out are submitting, or the back button (which still warns and logs).
- **The mobile Profile page now has real Payments and Support tabs.** Payments shows a student's actual payment/purchase history (subscriptions and course purchases). Support shows the same email/phone the public website's Contact page shows, plus a real "send us a message" form that goes straight into the same admin inbox the website's contact form already uses. Also moved the "Upgrade Plan" button off the Exams page and onto the Dashboard page (a colorful new icon), and renamed the Exams page's greeting to "Exam List."
- **Both the mobile app and the website now have a "Privacy & Legal" section** linking to the Terms of Service, Privacy Policy, and Cookie Policy — previously, a logged-in student had no way to reach any of those pages from inside the app or dashboard at all, only from the public marketing site's footer.
- **Checked into a reported "streak isn't working" issue — turned out not to be a bug.** The streak shown on the dashboard requires an exam attempt today or yesterday to stay active; the real database currently has no exam activity in the last two days at all (the most recent is from 2 days ago), so a streak of 0 is the mathematically correct result right now, not broken logic. Confirmed web and mobile use the exact same calculation, so this wasn't a mobile-only issue either.
- **A school's student limit is now actually enforced, not just displayed.** Every plan advertises a maximum number of students, but nothing ever stopped a school from adding more than their plan allowed — they could buy the cheapest plan and keep adding students indefinitely. Now, once a school hits its plan's limit, adding a student one-by-one, importing a batch by CSV, or a student joining with the school's invite code all get blocked with a clear message pointing at upgrading the plan, and the "Add Students" page shows a running "X of Y students used" banner before they even hit the wall.
- **Independent students (no school) can now sign up on the mobile app.** Previously the only way to create an account on the app was joining with a school's invite code — anyone without a school had no way to register on mobile at all, only on the website. Now there's a real "Sign up as an independent student" option right on the login screen. It creates the account and sends a verification email (same as everywhere else); picking a paid plan isn't part of the mobile signup itself — new accounts start on the free plan and can upgrade anytime afterward from the app's existing Upgrade Plan screen.
- **The word "Student" is now "Learner" throughout the product, user-requested.** Not every person using TYP (nursing-entrance prep, university-entrance prep, digital skills training) thinks of themselves as a "student" in the school sense, so login screens, dashboards, buttons, admin pages, legal pages, and emails on both the website and the app now say "Learner" instead. This is a wording change only — nothing about how accounts, roles, or permissions actually work changed underneath it.
- **The mobile app's Profile and Settings pages are reorganized into a single, simpler list**, user-requested. Payments and Support used to be separate tabs squeezed next to Profile, and Privacy & Legal was buried another tab deeper inside Settings — now Profile is one clean list: Settings, Payments, Support, and Privacy & Legal, each with a short description, plus a Sign Out button of its own right there (in addition to the one already in Settings) so logging out doesn't require digging into Settings first.
- **Course marketplace search can now reliably answer "are there Nursing courses?"** Previously courses were tagged with whatever free-text word a tutor typed, so the filter dropdown only ever showed categories that happened to already exist — there was no way to ask for "Nursing" and get a real, meaningful "not yet" answer. Courses are now tagged with a real Program (the same BECE/WASSCE/Nursing/University Entrance/Digital Skills list used everywhere else) — the catalog filter always shows all 5, even ones with zero courses right now, with an honest "No Nursing courses yet — check back soon" message instead of just hiding the option. Also fixed elsewhere on this page: the "+1 more features" text on the Enterprise plan in super admin's Subscription Plans page, which hid a feature with no way to actually see it — now shows every feature directly.
